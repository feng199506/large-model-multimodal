# 子任务说明（论文类别）

总任务：在 /root/large_model_multimodal_literature/ 建立“大模型与多模态模型”文献库。你负责两个论文类别，每类目标约 50 份**成功下载并通过全文核验**的独立论文资料。先读 scripts/pipeline_guide_cn.md（流水线、字段、命令、核验标准），严格按它操作。只用脚本 scripts/papers_en.py 下载；不要自己写下载代码，不要改 scripts/*.py（发现脚本缺陷就停下并在最终回报中说明）。不要改别的类别的种子/注释/结果文件，不要碰本目录以外的任何文件（尤其 /root/machine_learning_deep_learning_literature 和 /root/time_series_literature 只读）。

## 选题要求
- 以原始研究为主；适量纳入高质量综述（每类建议 ≤6）、学术教程、内容充分的官方技术报告。不收产品宣传、新闻、模型卡、仓库 README、普通博客、只有摘要的网页。
- 近三年窗口：首次公开（arXiv v1）≥ 2023-10-29。每类核验通过的资料中近三年 ≥ 85%（争取 ≥ 90%），三年前经典最多 5 篇，每篇写 old_reason（为何不可替代）。尽量覆盖 2025–2026 年的新工作（用 search 命令按日期检索，自行判断质量，不以热度/排行榜代替内容判断）。
- 每类兼顾本类所有子方向（见下），不要用同一模型系列的细小变体凑数（同一系列在一类中最多 2 篇，且需代表不同贡献）。
- arXiv ID 凭记忆给出时，resolve 会按标题核对并纠正；仍无法解析的就换题或用标题让脚本检索。不确定是否存在的论文不要写进种子。
- 边界：领域重叠时只定一个主分类，其余写进 cross（并写 cross_reason）。主分类约定：
  - 位置编码/长度外推方法→01；长上下文的使用、评测与检索→05。规模定律→01。文本扩散语言模型→01。
  - 数据污染检测→02（交叉 12）。合成数据用于预训练→02；用于指令微调→03。
  - RLHF/DPO/偏好奖励模型→03；为推理而做的 RL（如 GRPO、R1 类）、过程奖励模型、验证器→04。
  - 代码智能体、网页/计算机操作智能体及其评测→06；纯代码生成推理→04。
  - 事实性提升、引用、知识编辑→05；幻觉检测与度量、不确定性→12（多模态幻觉也放 12，交叉 07）。
  - 视觉语言模型、OCR/文档理解、多模态基准→07；视频理解、VLA、机器人、世界模型→10；图像/视频生成→08；语音/音频→09。
  - MoE、量化、蒸馏、KV 缓存、投机解码、分布式训练、推理服务→11。安全、隐私、偏见、可解释性、评测方法学→12。
- 同一论文全库只能有一个主分类（脚本的 claims 机制保证）。下载时如遇 duplicate_elsewhere，说明别的类别已认领，换题，必要时加 cross_only 条目。

## 流程
1. 为每类写种子：约 58 条主列表 + 10–15 条 reserve（备选也要合格、多样）。字段见指南。
2. resolve → download（默认 --target 50）→ status。对 failed/pending 逐条处理：pending 用 text 命令看首页，确属同一文献且完整才 manual（note 写明核对了标题/作者/正文完整）；failed 的换备选或补新候选，再 download。直到每类 50 篇核验通过，或可行候选耗尽（写明缺口原因）。
3. 核对 status 输出的近三年比例和三年前清单（≤5，且都有 old_reason）；子方向分布要均衡。
4. brief 生成摘要文件 → 阅读 → 为每篇已核验论文写注释（字段见指南）；只依据摘要/arXiv 注释/PDF 首页，禁止编造。每类选出优先阅读前 10 篇（top10_rank 1–10 + top10_reason）。
5. 每完成一类，确保种子/结果/注释都已落盘（它们就是断点）。

## 礼貌访问
脚本已对 arxiv.org/export.arxiv.org 做跨进程限速（另有其他会话在用同一 IP）。不要并行跑多个 download，不要自己用 curl 批量请求 arXiv。网页检索（WebSearch/WebFetch）可以用来找候选论文，但下载只走脚本。
